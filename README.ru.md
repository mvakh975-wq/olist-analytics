# Аналитика интернет-магазина Olist

[English version](README.md)

**Как рос бразильский маркетплейс, возвращаются ли покупатели и во что обходится опоздание доставки?** Полный цикл анализа на ~98 000 реальных заказов: модели dbt в DuckDB с тестами данных, статистический анализ в ноутбуках и публичный дашборд.

**[→ Открыть дашборд](https://mvakh975-wq.github.io/olist-analytics/)** (на английском)

## Ключевые выводы

Период анализа — январь 2017 – август 2018, только действительные заказы. Подробно и с рекомендациями — [`docs/findings.md`](docs/findings.md) (на английском).

1. **Рост дали новые покупатели, и в 2018 году он остановился.** Оборот (GMV) за январь–август 2018 — 8,59 млн BRL, в 2,4 раза больше, чем за те же месяцы 2017 года. Средний чек при этом не изменился (~160 BRL). Ни один месяц 2018 года не превзошёл ноябрь 2017-го с его Чёрной пятницей.
2. **Повторно почти никто не покупает.** 97% покупателей сделали ровно один заказ; в следующем месяце возвращаются лишь 0,48% когорты. Два сегмента «разовых покупателей с высоким чеком» — 38% клиентов и 68% выручки; это главная цель для программы второй покупки.
3. **Опоздание доставки сопровождается гораздо худшими отзывами.** Доставленные вовремя заказы получают в среднем 4,29 звезды, опоздавшие — 2,27 (−2,02; 95% ДИ от −2,06 до −1,98; тест Манна–Уитни p < 0,001). При опоздании на 4–7 дней 68% заказов получают 1–2 звезды против 9% при доставке вовремя. Разрыв сохраняется внутри каждого из 21 штата, где достаточно опоздавших заказов, и внутри пяти крупнейших категорий.
4. **Опоздания сосредоточены во времени и в регионах.** Доля опозданий за год выросла более чем вдвое (3,5% → 7,7% за январь–август), доходя до 12,4% в ноябре 2017 и 19,0% в марте 2018 при обычных ~3%; в Сан-Паулу, крупнейшем рынке, опаздывают 4,5% заказов, в Рио-де-Жанейро — 12,1%, в Мараньяне — 17,5%. Худшие 10% активных продавцов опаздывают в 15,3% своих заказов против 6,2% у остальных, но на них приходится лишь 11% всех опозданий.

## Как устроено

```
Kaggle (9 CSV) ─► scripts/download.py ─► data/raw/                        (не в git)
   ─► dbt + DuckDB: staging ─► intermediate ─► marts, 53 теста данных    (olist.duckdb, не в git)
   ─► scripts/export_marts.py ─► data/marts/*.parquet + статистика       (в git, ~19 МБ)
   ─► notebooks/: статистика и графики
   ─► site/: Observable Framework; главная и рост — из агрегатов, посчитанных при сборке,
             остальные страницы фильтруются в браузере через DuckDB ─► GitHub Pages
```

- **SQL-модели** ([`dbt/models`](dbt/models)): типизированный слой staging, одна обогащённая строка на заказ и витрины под каждый вопрос: `fct_orders`, `dim_customers`, `mart_monthly_kpis`, `mart_cohort_retention`, `mart_rfm`, `mart_delivery_performance` и другие.
- **Качество данных** ([`docs/data_quality.md`](docs/data_quality.md)): перед моделированием каждая таблица проверена на пропуски, дубликаты и типы, по каждой проблеме принято и записано решение. Тесты dbt охраняют ключи, связи, допустимые значения и бизнес-правила (например, задержка никогда не считается для недоставленного заказа).
- **Тесты** (pytest, 65): проект dbt собирается на выборке реальных строк, в которую специально включены все крайние случаи из профилирования, а итоги витрин сверяются с расчётом напрямую по сырым файлам. CI на каждый push: линтеры (ruff, sqlfluff), dbt build, pytest и сборка дашборда.
- **Проверка дашборда**: скрипт Playwright открывает каждую страницу на ширине компьютера и телефона в светлой и тёмной теме и падает при ошибках или горизонтальной прокрутке.

### Три вещи, которые данные пытались скрыть

- **`customer_id` — это не покупатель.** Olist выдаёт новый id на каждый заказ, поэтому удержание по нему ровно ноль. Человек — это `customer_unique_id`.
- **Один заказ — несколько отзывов.** У 547 заказов больше одного отзыва, и в 202 случаях оценки различаются. Для заказа берётся последний отвеченный отзыв; заказы без отзыва остаются пустыми, а не считаются нулём.
- **Пустые месяцы по краям.** Данные идут с сентября 2016 по октябрь 2018, но в первых и последних месяцах единицы заказов. Если их учитывать, искажаются все тренды, а самые новые когорты выглядят так, будто никто не вернулся.

## Как запустить

Нужны [uv](https://docs.astral.sh/uv/), Node.js 20+ и бесплатный аккаунт Kaggle (`uv run kaggle auth login` или токен в `~/.kaggle/access_token`; либо скачайте архив вручную в `data/raw/`).

```bash
uv sync
make data build export    # скачать CSV, собрать и проверить модели dbt, выгрузить витрины
make site                 # дашборд на http://127.0.0.1:3000
```

`make test` — тесты, `make lint` — линтеры. Ноутбуки читают `olist.duckdb`; запуск — `uv run jupyter lab`.
